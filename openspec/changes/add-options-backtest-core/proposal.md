## Why

目前没有任何可运行的回测代码，而使用者的目的是**用回测把七个策略组件的细节定下来**。其中前四个（regime、entry、take profit、stop loss）的规则都不依赖组合状态，因此不需要逐日模拟——用表操作一次算完即可，速度快两个数量级，适合参数扫描与分组研究。

事件驱动引擎在 positioning、hedge、展期这类需要组合状态的研究出现时才必需，排在后面（见 `ROADMAP.md` 阶段 4）。本变更先建地基与成交表引擎，使研究能尽早开始。

## What Changes

**地基（两个引擎共用）**

- 数据访问层：标的日线（**同时提供复权价与实际成交价**）、期权链接口、无风险利率序列、分红事件、交易日历、本地缓存。期权链接口按商业数据源的通用字段集定义，某实现提供不了的字段标记为不可用而非从接口移除
- 合成期权链生成器，填满同一接口。用途被 spec 限定为引擎验证与标的信号层研究，**明确禁止用于期权侧参数调优**
- Black-Scholes 定价、希腊字母、隐含波动率反解——**作为合成链的内部工具**而非独立一层；两个明确分工的时间口径（定价用日历日/365、波动率年化用交易日/252）
- 合约选择：按 DTE、目标 delta、价值状态选约，含流动性过滤、可执行性下限与可解释的筛选过程
- 信号层基础：技术指标、统一信号接口，由截断重算属性测试保障无前视
- 成本模型：取价规则、佣金、交易所与监管费、滑点、可成交性判定——**两个引擎共用同一套成本假设**

**成交表引擎**

- 枚举候选入场 → 按规则选约 → 查入场报价 → 由持有窗口内的逐日报价判定**最早触发**的了结条件 → 产出交易明细
- 支持参数批量扫描，各组独立且结果确定
- **显式拒绝**它无法正确处理的配置（展期、依赖权益的仓位规模、组合层约束），而非给出近似结果
- 强制披露其固有口径：各笔独立计算、不含资金约束、无组合权益曲线；输出同时持仓数分布使资金缺口可见

**统一交易明细格式**

- 定义单一的交易记录格式，两个引擎的产出都必须符合，使研究与报告层完全通用
- 每条记录携带入场与了结时的上下文变量（标的价、IV、DTE、价值状态、delta、市场状态），且可由使用者扩展——这是任意事后分组研究的物理前提
- 一条记录对应一笔**逻辑交易**，可跨多个合约与多笔成交

**交易层报告**

- 交易统计（基于逻辑交易）、单笔盈亏分布（含尾部分位、偏度峰度）、成本分项与扣费前后对照、导出、可复现性与回归基线、合成数据披露
- **不含**回撤、夏普、资金占用——这些依赖组合权益曲线，在事件驱动引擎具备后才成立

## Capabilities

### New Capabilities

- `market-data`: 标的行情（两套价格）、期权链接口、利率与分红、交易日历、合成链、缓存与质量校验
- `option-pricing`: Black-Scholes 定价、希腊字母、IV 反解、双时间口径、美式近似与合成链循环性的披露
- `underlying-signals`: 技术指标、统一信号接口与无前视保证
- `contract-selection`: 按 DTE / delta / 价值状态选约，流动性过滤与可执行性下限
- `trading-costs`: 取价规则、费用模型、滑点、可成交性判定
- `trade-record`: 统一的交易明细格式、入场与了结上下文、逻辑交易、了结原因取值集合
- `trade-table-engine`: 候选枚举、首次触发判定、盈亏计算、不适用情形的拒绝、口径披露、参数扫描
- `performance-report`: 交易统计、盈亏分布、成本影响、导出、可复现性、合成数据披露

### Modified Capabilities

（无，本项目首个变更）

## Impact

- **新建代码**：Python 包 `backtest/`，含 `data/`、`signals/`、`selection/`、`costs/`、`engine/`、`report/` 六个模块（定价作为合成链的内部工具位于 `data/synthetic/`）
- **新增依赖**：`pandas`、`numpy`、`scipy`、`yfinance`、`pyarrow`、`pandas_market_calendars`、`pytest`，版本锁定
- **结论边界**：合成链下只有依赖标的真实价格的结论（信号层、regime）有效；期权侧的选约、止盈、止损参数在本阶段**不做研究**
- **对后续阶段的约束**：期权链接口的字段集与交易明细格式一旦定型，事件驱动引擎与真实数据源都必须遵守；两个引擎在无资金约束下必须产出相同的交易明细，这是阶段 4 的核心验收项
