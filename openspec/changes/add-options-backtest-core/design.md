## Context

空仓库，无既有代码约束。三项现实条件塑造了本设计（动机见 proposal.md - Why）：

1. **无真实期权链数据**，使用者后期会买。接口形态必须按商业数据源来定，而不是按合成链能提供什么来定
2. **使用者要用回测定策略细节**，因此首要交付物是能开始研究的东西，而非完整系统
3. **前四个组件的规则不依赖组合状态**，因此不需要逐日模拟

技术栈 Python：pandas / numpy / scipy / yfinance / pyarrow / pandas_market_calendars / pytest。

## Goals / Non-Goals

**Goals:**

- 跑通"信号 → 选约 → 入场 → 首次触发了结 → 交易明细 → 交易层报告"的完整链路
- 地基（数据、定价、选约、信号、成本）对两个引擎通用，事件驱动引擎届时只新增编排层
- 交易明细格式定型，成为研究层与两个引擎之间的唯一契约
- 全链路无前视，由属性测试保障；结果确定性可复现

**Non-Goals:**

- 不做组合记账、权益曲线、资金约束（阶段 4）
- 不做展期、对冲、组合层风控（阶段 4、7）
- 不做参数搜索的统计评估——扫描本身在本阶段，证据分级与多重检验在阶段 2
- 不做真实数据接入（阶段 6）
- 不拟合波动率曲面

## Decisions

### 决策 1：两个引擎共用地基，产出同一张交易明细表

数据、定价、选约、信号、成本五块对两个引擎完全通用；两者的产出符合同一个交易记录格式。

**理由**：这是整个架构最关键的一条。它带来三个后果——研究与报告层写一次即可通用；成本假设不可能在两条路径上分叉；以及最有价值的一点：**可以做双引擎一致性校验**——同一策略配置在无资金约束、无并发上限的条件下，两条引擎必须产出逐行相同的交易明细。这是一个极强的正确性测试，任何一边的逻辑错误都会被对方照出来。

**代价**：成交表引擎不能走捷径（比如用中价简化成本），必须走同一套成本模型。这正是想要的约束。

### 决策 2：止盈止损用"首次触发查表"，不用逐日推进

判定方式是：拉出入场合约在持有窗口内的逐日报价序列，算出每日相对入场价的盈亏比例，取第一个越过阈值的日期。

**理由**：常见的误解是"止盈止损是路径依赖的，必须模拟"。实际上它需要的只是该合约的日价格序列，而那是一次查询。几万笔交易用一次 groupby 即可完成，比逐日循环快两个数量级。

**边界**：这个方法对"了结条件只依赖该合约自身路径"的规则成立。一旦规则引用组合状态（可用现金、总敞口）或其他持仓，就不再成立——那类配置由决策 3 显式拒绝。

### 决策 3：不适用的配置显式拒绝，不给近似结果

成交表引擎遇到展期、依赖权益的仓位规模、组合层约束、跨持仓对冲时，启动即报错并指明需要事件驱动引擎。

**理由**：给近似结果是最坏的选项——使用者拿到一个看起来正常的数字，却不知道它对应的规则并没有被真正执行。报错很烦人，但错误的数字更贵。

### 决策 4：成交表的口径必须强制披露

每份基于成交表的报告都标注：各笔交易独立计算、不含资金约束、无组合权益曲线；同时输出每日同时持仓数序列与其最大值。

**理由**：成交表会系统性高估可行性。若规则某段时间产生 30 笔重叠持仓，它照单全收，不管账上有没有钱。输出并发持仓分布，使这个缺口从"看不见"变成"一眼可见"。当按配置的单笔规模推算出的资金需求超过设定规模时，直接警示该结果在资金上不可实现。

### 决策 5：接口按商业数据源定义，合成链去填满它

期权链字段集按 ORATS / Polygon 一类商业数据源的通用输出定义（bid/ask/last/volume/open_interest/iv/四希腊字母/标的价/来源/质量标记）。合成链提供不了的字段标为不可用，**而不是从接口里删掉**。

**理由**：如果接口按"合成链能给什么"来定，等买了真实数据会发现字段对不上，接口得重做——预留的扩展点白留。倒过来定，接入真实数据只是新增一个实现。

### 决策 6：合成链的用途在 spec 层面被限定

只允许用于引擎验证、测试夹具与标的信号层研究；期权侧参数调优被明确禁止，报告层强制标注。

**理由**：合成链没有波动率偏斜、没有真实的隐含波动率动态、没有随流动性变化的价差。在其上调止盈止损，调出的是"该合成模型下的最优解"，与真实市场无关——不是"有偏差可修正"，而是"无关"。把这条写进 spec 而非留作口头约定，是因为半年后没人会记得。

**替代方案**：把合成模型做精细（加偏斜、加 IV 动态）。否决——没有真实数据校准，加进去的每一条仍是编的，而精致的假数据比粗糙的假数据更危险。

### 决策 7：标的价格分为复权价与实际成交价两套

复权价用于信号与收益率计算；实际成交价用于与期权链行权价对齐、计算价值状态、以及作为定价模型的标的输入。

**理由**：期权行权价是当时的实际价格，而复权价会被后续分红与拆股不断改写。用复权价判断历史合约的价值状态，误差随累计分红单调增大——QQQ 十年累计分红超过 5%。这类错误的隐蔽之处在于它不会报错，只会让所有历史选约系统性偏移。

### 决策 8：时间口径是两个而非一个

定价的到期时间与 theta 衰减用**日历日 / 365**；波动率年化用**交易日 / 252**。两者显式声明。

**理由**：期权在周末照常衰减，用交易日计会系统性低估时间成本；波动只在交易日产生，用日历日年化会低估波动率。强行统一必错其一。

### 决策 9：无风险利率与分红是时间序列，不是常数

利率按交易日取值；分红率由存续期内的实际除息事件导出。

**理由**：区间横跨近零利率与 5% 利率时，常数利率对长期限合约的定价是实质扭曲。分红则同时影响定价与提前行权判断，用年化常数会抹掉除息日这个关键时点。

### 决策 10：定价是合成链的脚手架，不是架构的一层

Black-Scholes 定价与希腊字母放在 `data/synthetic/` 之下，作为合成链生成器的内部工具，而非与 `data`、`selection`、`engine` 平级的模块。

**理由**：定价在本阶段的用途几乎全部是"因为没有真实数据"——生成合成报价、算出用于选约的 delta。商业数据源直接提供报价与希腊字母，届时这些代码的调用方只剩下盈亏归因（阶段 2）中数据商未提供希腊字母的情形。把它摆成一层，会让人误以为定价是回测系统的核心职责，而实际上一个有真实数据的回测系统可以完全不含定价代码。

**保留的部分**：隐含波动率反解与希腊字母计算作为工具函数保留，供归因在数据缺字段时回退使用。

### 决策 11：欧式模型用于美式期权是显式近似

以 Black-Scholes 为定价核心，但记录标的期权的实际行权方式，并标注近似失效的情形——主要是深度实值看涨期权在除息日前存在提前行权价值时。

**理由**：对买方的虚值与平值期权，欧式近似误差在千分之几量级，换二叉树得不偿失。但"误差小"不等于"可以不说"。

### 决策 12：合约标识用可读的确定性字符串

形如 `QQQ_20240315_C_00400000`。可读，便于在交易明细里肉眼核对；确定性，保证跨运行可复现；不依赖外部代码表。

### 决策 13：期权链以"每日快照的长表"为统一数据结构

每行一个合约在某日的报价，主键 `(asof, symbol, expiry, strike, right)`。

**理由**：合约生死不定，宽表极度稀疏。长表适合 parquet 列式存储与按日切片，更重要的是它**直接适配成交表引擎的 join 操作**——首次触发判定本质上就是在这张长表上按合约与日期范围切片。

### 决策 14：信号在回测开始时一次性全序列计算

引擎按日切片取用，而不是逐日增量计算。

**理由**：性能。风险是前视——一次性计算时容易不小心用到未来数据。该风险由决策 18 的截断重算属性测试兜底。这是有意识的取舍：用测试换性能，而不是用架构换性能。

### 决策 15：无前视由"截断重算"属性测试保障

随机抽取日期 t，把输入截断到 t 重算该日的全部信号与选约决策，断言与完整数据下逐位一致。

**理由**：前视偏差最致命且最难靠肉眼发现。代码审阅会漏，这类测试不会。

### 决策 16：统一的「可缺失值」类型，禁止裸 None 与哨兵值

所有跨模块传递的数值用统一类型表达"有值 / 无值 + 无值原因"。

**理由**：缺失值会出现在每一个模块。若每处各写各的判断，会迅速出现判断逻辑不一致，且总有一处把缺失当成零——一个被当成 0 的缺失 delta 会让选约选出完全错误的合约，而回测照常跑完。

### 决策 17：确定性作为硬约束

所有排序与并列取舍必须有确定性规则；随机性由显式种子控制并记入配置；依赖版本锁定；维护回归基线。

**理由**：研究靠反复对比"改一处之后差多少"。基线不稳定则一切对比失去意义。

### 决策 18：模块内不做缓存，缓存只在数据层

`pricing`、`signals`、`selection` 为纯函数；仅 `data` 层落地 parquet 缓存，缓存键涵盖标的、区间、数据源、价格类型与生成参数。

**理由**：纯函数易测且无隐藏状态；可复现性只需管住一个地方。

## 内部设计

### 成交表的生成流程

```
1. 由入场条件筛出候选入场日            ← 只依赖信号与市场状态
2. 每个候选日按选约规则确定合约         ← selection
3. 查入场报价，判定可成交性             ← trading-costs；不可成交则剔除该候选
4. 拉出该合约在持有窗口内的逐日报价序列   ← data，一次切片
5. 算每日相对入场价的盈亏比例
6. 取各了结条件中最早触发者              ← groupby + first
7. 查了结报价，计算净盈亏
8. 附上入场与了结时的上下文变量           → 交易明细一行
```

第 4 至 6 步是全部批量完成的，不存在逐笔循环。

### 核心数据结构

跨模块传递的对象不可变；批量数据用带 schema 校验的表，禁止裸 dict。

| 结构 | 含义 |
| --- | --- |
| `Bar` | 标的某日行情，含复权与实际成交两套 OHLCV |
| `ChainSnapshot` | 某日全部合约报价，长表 |
| `ContractId` | 可读的确定性合约标识 |
| `TradeRecord` | 一笔逻辑交易的完整记录，含两端上下文 |
| `Maybe[T]` | 可缺失值：有值，或无值 + 原因 |

### 六个模块

| 模块 | 职责 | 性质 |
| --- | --- | --- |
| `data` | 行情、链、利率、分红、日历、缓存；合成链（含其内部的定价工具） | 唯一持有外部依赖与缓存 |
| `signals` | 指标、信号接口、无前视 | 纯函数 |
| `selection` | 选约规则与筛选过程 | 纯函数 |
| `costs` | 取价、费用、滑点、可成交性 | 纯函数 |
| `engine` | 成交表生成与编排 | 唯一的编排者 |
| `report` | 交易统计、分布、成本分项、导出 | 纯函数，只读交易明细 |

依赖严格单向：`report` ← `engine` ← {`selection`, `costs`, `signals`} ← `data`，由自动化检查强制。

定价代码位于 `data/synthetic/pricing.py`，是合成链的实现细节；`selection` 与 `engine` MUST NOT 直接导入它——它们消费的是链上的报价与希腊字母字段，不关心这些数字是真实观测还是模型生成。这条约束保证接入真实数据时上层零改动。

### 错误处理策略

分三层，界限明确：

1. **启动时失败** —— 配置缺失或互相冲突、信号名不存在、配置了成交表引擎不支持的规则、数据源与配置不兼容
2. **运行中记录为事件，不抛异常** —— 报价缺失、选约失败、合约不可成交、了结日顺延。这些是市场的正常状态，应当继续并计入统计
3. **运行中失败** —— 盈亏计算不守恒、状态自相矛盾这类表示代码有 bug 的情形

第 2 类最容易做错：当异常处理会让回测跑不完，静默吞掉会让统计失真。正确做法是进入一份可查询的事件流。

## Risks / Trade-offs

- **成交表口径被误读为完整回测结论** → 强制披露 + 并发持仓分布 + 资金不可行时的显著警示；spec 级要求而非文档约定
- **合成链结论被误当作真实 edge** → spec 限定用途 + 报告强制标注 + 期权侧参数搜索被拒绝，三重约束
- **单一波动率使买方成本被系统性低估**（真实市场 OTM 期权 IV 更高，买方买得更贵）→ 偏差方向明确：合成链下买方绩效偏乐观，真实数据下只会更差
- **两套价格增加用错的可能** → 接口上分开命名并加断言；另设对齐测试：历史合约的价值状态判定必须与当时实际价格一致
- **首次触发判定在报价稀疏时失真**（缺报价的日子可能恰好是应触发的日子）→ 跳过的天数被记录并纳入统计；若跳过比例高，该笔结果的可信度在阶段 2 被降级
- **地基为两个引擎设计，当前只有一个用户** → 接受。地基的复用是本设计的主要价值，且双引擎一致性校验需要它

## 基准配置

首次回测的默认取值。这不是"正确参数"，而是**基线**——研究时每一次变体对比都相对它而言。

### 标的与区间

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 标的 | QQQ（单标的起步） | SPY 待引擎稳定后加；两者相关性约 0.95，届时按相关样本处理 |
| 合约规格 | 美式、实物交割、乘数 100 | QQQ 期权的实际规格 |
| 区间 | 2015-01-01 ～ 2024-12-31 | 覆盖 2018Q4、2020、2022 三次不同性质的下跌，以及零利率与 5% 利率两个周期 |
| 名义资金 | 100,000 美元 | 成交表引擎不做资金约束，该值仅用于把盈亏折算为比例、以及判断并发持仓的资金可行性 |

### 执行与成本

| 项 | 取值 |
| --- | --- |
| 成交价 | 取不利端（买 ask、卖 bid）；中价成交作为对照选项 |
| 券商佣金 | 0.65 美元/张，每单最低 1.00 美元 |
| 交易所与监管费 | 0.05 美元/张 |
| 额外滑点 | 0（价差已是主要成本；滑点作为敏感性分析变量） |
| 最大相对价差 | 超过 20% 判定为不可成交 |

### 定价输入

| 项 | 取值 |
| --- | --- |
| 无风险利率 | FRED 三个月期国债收益率**序列** |
| 分红 | 标的实际除息事件 |
| 波动率代理 | QQQ 用纳斯达克 100 波动率指数；SPY 用标普 500 波动率指数 |
| 定价时间口径 | 日历日 / 365 |
| 波动率年化口径 | 交易日 / 252 |

### 合成链生成

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 行权价步长 | 1 美元，对齐真实市场 | 使合成链与日后的真实数据同构 |
| 行权价覆盖 | 标的价 ±20% | 覆盖中频策略可能用到的全部价值状态 |
| 到期集合 | 标准月度 + 周五周度（按历史推出时点） | 使"选 30DTE"的可得性真实 |
| 买卖价差 | 理论价的 2%，下限 0.05 美元 | 粗糙但方向明确，刻意不做精细 |

### 基线策略（仅用于打通链路）

均线信号入场 → 选约 30 DTE、目标 delta 0.30 看涨 → 持有 10 个交易日 / 盈利 100% / 亏损 50% / 剩余 5 个交易日，先达者了结。单笔固定 1 张。

这套规则**没有任何 edge 主张**，唯一用途是让引擎跑起来并产出第一张交易明细表。
