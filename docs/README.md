# `docs/`

Every document in this project, except the four files the root keeps for a mechanical
reason. The division is by **what makes a document wrong**, because that is what decides
who may change it and when.

## The standing documents

Continuously maintained, no beginning and no end. These are the project's account of
itself, and they are wrong when the code outgrows them.

| File | What it is | What makes it wrong |
|---|---|---|
| [`conventions.md`](conventions.md) | the rulebook: the guards, the failures this project refuses, and why | a guard it describes stops existing, or one exists that it does not name |
| [`requirements.md`](requirements.md) | what is built against the architecture, criterion by criterion, with reasons for what is not | it says a thing is absent after it was built — the most common rot here, and the hardest to see |
| [`research-questions.md`](research-questions.md) | what the platform exists to answer | a question is marked runnable when the tooling for it does not exist |

## The architecture, and its originals

| Path | What it is | What makes it wrong |
|---|---|---|
| [`architecture.md`](architecture.md) | the architecture, transcribed from the PDF. Sections are citable by number: 5.1 is `architecture.md#section-5-1` | **nothing.** It is a transcription; the PDF is the original. A disagreement with the code is unfinished work (`requirements.md`) or a deliberate deviation (`conventions.md`) |
| [`frontend-web-plan.md`](frontend-web-plan.md) · [`ui-ux-design-plan-addendum.md`](ui-ux-design-plan-addendum.md) | the interface plans, same arrangement | as above |
| `originals/` | the three source PDFs | nothing. They are the originals |

All three Markdown files are generated by `tools/pdf_to_md.py` from `originals/`. **Nothing
edits them by hand** — a regeneration would undo it silently. `doc-keeper` is blocked from
all four paths by a hook, `originals/` included, since it sits inside the `docs/` it owns.

## The documents with a lifecycle

| Directory | What is in it | What makes one wrong |
|---|---|---|
| [`plans/`](plans) | a piece of work with a beginning and an end, plus its progress file and report | it stops being followed. A plan nobody is working from is history, not a plan |
| [`specs/`](specs) | one file per feature: goal, non-goals, acceptance criteria, the tests that prove them | the thing was built differently. Then the spec is amended, or it is not the spec |
| [`decisions/`](decisions) | one file per decision: context, options, choice, why, consequences | **a decision never goes stale.** It records what was known at the time. Superseded, never edited |
| [`findings/`](findings) | a research result: data, method, baselines, result, caveats | its data or configuration is misstated. A result that turned out otherwise is still a finding |
| [`research/`](research) | [`plan.md`](research/plan.md) — which question is next and why — and benchmark reports | the plan does not say what would make us abandon a question |
| [`ideas/`](ideas) | [`backlog.md`](ideas/backlog.md): candidate directions with their scores | a score with no evidence behind it |
| [`feedback/`](feedback) | observations from real use. **Written by the human, read by agents** | an agent writes one. It is the one input nothing in this repository can derive |
| [`radar/`](radar) | weekly scout digests, plus [`seen.md`](radar/seen.md) and [`ignore.md`](radar/ignore.md) | an item with no answer to "what does this mean for this project" |

## Two things that hold across all of them

**A document that contradicts the code is a bug in the document.** `tools/check_docs.py`
runs the Python in `README.md` and `tools/check_doc_claims.py` checks stated claims against
`requirements.md`, but neither reads prose. The `doc-keeper` agent covers the rest, and the
rule it works by is that the document is corrected and never the code — a document is a
claim about the code, not evidence about it.

**Everything here is in English**, like the rest of the project, and
`tools/check_language.py` fails otherwise. The reason is the same as for code: a section
cited by two names is a section the citation stops finding.

## What the root still keeps, and why

Not a judgement about importance — each is there because something reads it there:

- **`README.md`** — GitHub's landing page, and `tools/check_docs.py` runs its Python blocks
  by that name.
- **`CLAUDE.md`** — loaded by directory. The area files sit in
  [`backtest/`](../backtest/CLAUDE.md), [`app/`](../app/CLAUDE.md) and
  [`tests/`](../tests/CLAUDE.md) for the same reason.
- **`run_backtest.py`** — an entry point. Its own docstring is `python3 run_backtest.py`,
  and its `sys.path` line assumes the root.
- **`pyproject.toml`**, **`pytest.ini`**, **`.gitignore`** — read by tools that look at the
  root and nowhere else.

An earlier version of this file argued that `conventions.md`, `requirements.md` and
`research-questions.md` had to stay at the root too, "cited by the guards, and moving them
would break every pointer in the code for nothing." That was wrong twice over, and it is
worth leaving the correction visible: only `requirements.md` was ever read by a guard — by
three of them, now pointed at `docs/requirements.md` — and `conventions.md` and
`research-questions.md` were read by no code at all. The pointers were counted rather than
assumed, and the move cost fifteen markdown links and four read paths.

## What is deliberately not here

**`/research/` at the repository root** — the local research record: run history, trade
logs, `research.db`. Not version controlled, and your asset rather than code. It is not
documentation, and it is not `docs/research/`, which is the plan, nor `backtest/research/`,
which is code. The leading slash in `.gitignore` is what separates the three.
